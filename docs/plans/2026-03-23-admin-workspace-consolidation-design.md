# 后台工作台合并设计

日期: 2026-03-23
状态: Approved
范围: 管理台工作台信息架构、视觉收敛、文案修正

## 1. 背景

当前管理台将 `概览`、`模型`、`提示词` 拆成多个 tab，同时保留了 `工作空间`、`发布` 等未接入真实后端能力的界面。这导致两个问题:

- 核心编辑流程被切碎，日常操作需要频繁切 tab
- 页面暴露了假数据、占位按钮和暂不支持的功能

目标是将管理台收敛为一个真正可用的主工作台，并保持与现有后台一致的审美体系。

## 2. 目标

本次改造目标:

1. 将 `概览`、`模型`、`提示词` 合并成一个主工作台
2. 顶部 tab 收敛为 `工作台` 和 `Skills`
3. 仅展示当前真实支持的内容和操作
4. 文案统一将 `场景 ID` 修正为 `场景编码`
5. 视觉上保持现有后台的玻璃质感、冷静蓝色和克制布局

非目标:

- 不新增后端能力
- 不保留工作区绑定、发布流程、性能指标等占位内容
- 不修改 Skills 页的核心交互

## 3. 方案选择

### 方案 A: 单列纵向编辑页

将基础信息、模型配置、提示词按顺序排成单列。

优点:

- 实现简单
- 移动端适配直接

缺点:

- 首屏缺少上下文
- 提示词编辑区不够突出

### 方案 B: 顶部摘要 + 下方双栏工作台

顶部展示场景摘要，下方左侧放基础信息和模型配置，右侧放提示词编辑器。

优点:

- 最符合后台日常编辑路径
- 上下文完整
- 提示词编辑区能成为主视觉

缺点:

- 布局改造范围更大

### 方案 C: 单页 + 分段切换器

仍保留页内切换器区分三块内容，但不再使用顶部 tab。

优点:

- 比原方案更收敛

缺点:

- 依然存在内容被切换打断的问题
- 不够像真正的合并页

最终选择: 方案 B。

## 4. 信息架构

### 4.1 顶部导航

管理台顶部仅保留两个 tab:

- `工作台`
- `Skills`

移除:

- `概览`
- `模型`
- `提示词`
- `工作空间`
- `发布`

### 4.2 工作台结构

工作台采用三段式布局:

1. 顶部摘要条
2. 左侧设置区
3. 右侧提示词主编辑区

顶部摘要条仅展示真实信息:

- 场景名称
- 场景编码
- 基础场景来源
- 当前状态

左侧设置区包含:

- 基础信息
- 模型配置

右侧主编辑区包含:

- 系统提示词编辑器

### 4.3 Skills

`Skills` 保持独立 tab，不在本次改造中引入新的信息架构变化。

## 5. 内容收敛

### 5.1 保留内容

- 场景名称
- 场景编码
- 场景描述
- 基础场景来源
- 模型服务地址
- 模型名称
- 系统提示词

### 5.2 移除内容

- 交互性能指标
- 平均延迟、准确率、Token 效率等假数据
- 草稿版本号
- 对比版本、同步基准等快捷操作
- 发布面板与发布按钮
- 工作区绑定静态列表

## 6. 文案规则

- 所有 `场景 ID` 统一替换为 `场景编码`
- 区块标题使用产品工作台语言，不使用宣传式文案
- 说明文案只描述范围、行为和保存结果，不引入未来规划

## 7. 交互设计

### 7.1 保存行为

保存保持分区进行:

- 基础信息单独保存
- 模型配置单独保存
- 提示词单独保存

这样可以复用现有接口和 mutation，不改变后端交互语义。

### 7.2 状态反馈

- 每个区块保留自己的保存按钮
- 保存中只反馈该区块状态
- 不增加跨区联动提交

### 7.3 响应式

桌面端:

- 顶部摘要横向展开
- 下方采用双栏布局

移动端:

- 自动收敛为单列
- 顺序为摘要、基础信息、模型配置、提示词

## 8. 视觉方向

visual thesis:
在既有蓝白玻璃质感后台中，将页面从“伪数据仪表盘”收敛为“高密度、克制、精致的编辑工作台”。

content plan:

- 顶部摘要负责定位当前场景
- 左栏负责配置
- 右栏负责主要编辑
- 不再保留与真实操作无关的收尾区块

interaction thesis:

- 页面首屏采用轻量错峰进入
- 输入区 focus 提升边界和光感
- tab 切换采用克制透明度过渡

## 9. 实现拆分

### 9.1 前端组件

- `frontend/src/pages/AdminPage.tsx`
  - 收敛 tab 结构
  - 接入新的工作台组件
- `frontend/src/components/admin/AdminWorkspacePanel.tsx`
  - 新增合并后的主工作台组件
- `frontend/src/components/admin/AdminOverviewPanel.tsx`
  - 不再作为独立入口使用，可移除或并入新组件
- `frontend/src/components/admin/PromptPanel.tsx`
  - 不再作为独立入口使用，可移除或并入新组件
- `frontend/src/styles/admin.css`
  - 新增工作台布局与动效样式
  - 删除与已移除面板相关的样式依赖

### 9.2 测试

- `frontend/src/test/admin-page.test.tsx`
  - 更新 tab 数量与默认内容断言
  - 验证 `场景编码` 文案
  - 验证已移除的占位内容不再出现
  - 保留模型配置与提示词保存行为验证

## 10. 风险与约束

- 需要谨慎处理现有 CSS，避免影响 Skills 页和侧边栏
- 合并组件后仍需保证已有 API 保存路径不变
- 假数据与占位区块移除后，页面需要通过层级、版式和输入区尺寸维持足够的信息密度
