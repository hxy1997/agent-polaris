# 技能管理模块简化设计

日期: 2026-03-23
状态: Approved
范围: 管理台技能模块, 图标依赖替换

## 1. 背景

当前管理台技能模块具备完整文件管理能力:

- 新建技能
- 新增文件
- 新增目录
- 重命名
- 删除
- 右键菜单
- 在线编辑

这套能力对当前后台使用目标来说过重, 也提高了交互复杂度。用户希望将其简化为一个更接近 GitHub 仓库浏览的技能浏览器:

- 上传完整技能文件夹
- 删除技能
- 左键点击目录时展开或收起
- 左键点击文件时在右侧预览内容

同时, 当前前端图标依赖 Google 的 `Material Symbols Outlined`, 在受限网络或部分内网环境中存在渲染失败风险, 需要替换为本地可用方案。

## 2. 目标

本次改造目标:

1. 将技能模块收敛为 `上传 + 删除 + 树形浏览 + 只读预览`
2. 上传目标固定为当前场景的 `skills/<上传文件夹名>`
3. 目录与文件的左键行为明确区分
4. 删除破坏性操作保留确认
5. 移除 Google 图标字体依赖, 改用本地 SVG 图标

非目标:

- 不支持上传到任意子目录
- 不支持在线编辑技能文件
- 不支持在 UI 中新建文件或目录
- 不支持重命名技能节点
- 不处理本地字体包托管, 仅移除图标外链依赖

## 3. 方案选择

### 方案 A: 目录上传 + GitHub 风格文件树 + 只读预览

用户通过目录选择器上传完整技能文件夹。系统将目录内容写入当前场景 `skills/<上传文件夹名>`。左侧树采用仓库浏览样式, 顶级技能和子目录都支持左键展开; 文件左键选中后在右侧只读预览。

优点:

- 与目标最一致
- 操作心智最简单
- 保留技能结构的可见性

缺点:

- 需要新增 multipart 上传接口
- 前端需要重写技能树交互

### 方案 B: zip 上传 + 只读浏览

用户上传 zip, 后端解压到技能目录。

优点:

- 后端实现简单

缺点:

- 用户体验退化
- 增加压缩包准备步骤

### 方案 C: 保留现有文件管理器, 只隐藏部分按钮

优点:

- 改动最小

缺点:

- 交互复杂度仍然过高
- 不符合简化目标

最终选择: 方案 A。

## 4. 交互设计

### 4.1 页面结构

技能页保留左右两栏:

- 左栏: 技能树 + 上传 / 删除操作
- 右栏: 文件只读预览

### 4.2 左栏行为

顶部工具区仅保留:

- `上传技能`
- `删除技能`

删除按钮只在选中顶级技能目录时可用。

树形行为:

- 点击目录整行: 展开或收起
- 点击文件整行: 选中并高亮
- 目录不触发右侧文件预览
- 文件会在右侧展示内容

视觉方向参考 GitHub 仓库文件树:

- 小三角表示展开状态
- 行高紧凑
- 选中态清晰但不过度强调
- 图标使用本地 SVG

### 4.3 右栏行为

右侧只保留预览:

- 选中文件时展示文件名、来源、内容
- 选中目录时展示空态提示
- 不提供编辑、保存、复制基础技能等操作

## 5. 上传设计

### 5.1 前端

上传入口使用目录选择器:

- `input type="file"`
- `multiple`
- `webkitdirectory`

前端提交 multipart 表单:

- `folder_name`: 上传目录名
- `files`: 文件内容数组
- `paths`: 每个文件在目录内的相对路径

约束:

- 必须存在至少一个文件
- 目录名不能为空
- 前端不允许空上传

### 5.2 后端

新增接口:

- `POST /api/admin/scenes/{scene_id}/skills/upload`

后端逻辑:

1. 校验场景存在
2. 校验 `folder_name`
3. 目标目录固定为 `scene skills root / folder_name`
4. 若目标已存在则报错
5. 按相对路径逐个写入文件
6. 禁止路径逃逸, 禁止 `..` 与绝对路径
7. 返回最新技能树

约束:

- 不支持覆盖上传
- 不对上传内容做额外模板修正
- 保留原始文件结构

## 6. 删除设计

删除仍复用现有删除接口, 但前端只允许删除顶级技能目录。

规则:

- 删除前弹出确认
- 确认文案包含技能名
- 删除后清空选中态, 并刷新技能树

## 7. 图标替换设计

当前问题:

- `frontend/index.html` 通过 Google Fonts 外链引入 `Material Symbols Outlined`
- 多个页面依赖 `.material-symbols-outlined`

改造方案:

- 新增本地 React SVG 图标组件
- 按当前页面实际使用的图标提供命名导出
- 所有 `material-symbols-outlined` 替换为本地图标组件
- 删除 `Material Symbols` 外链和相关样式依赖

本次覆盖范围:

- 管理台
- 对话页
- 输入框附件菜单

## 8. 数据流与实现拆分

### 8.1 后端

- `app/schemas/admin.py`
  - 增加上传请求处理所需定义
- `app/api/admin/scenes.py`
  - 增加上传技能目录接口
- `app/services/skill_service.py`
  - 增加上传目录服务逻辑
- `app/storage/skill_repository.py`
  - 增加批量写入目录方法

### 8.2 前端

- `frontend/src/lib/api.ts`
  - 增加上传技能目录请求
- `frontend/src/hooks/useScenes.ts`
  - 增加上传 mutation
- `frontend/src/components/admin/SkillPanel.tsx`
  - 重写为简化版技能浏览器
- `frontend/src/components/common/`
  - 新增本地图标组件

## 9. 错误处理

上传失败需给出可操作提示:

- 技能已存在
- 目录为空
- 文件路径非法
- 场景不存在

删除失败需保留已有错误提示通道。

预览失败:

- 文件读取失败时在右栏显示错误消息

## 10. 测试策略

后端测试:

- 上传技能目录成功
- 上传到已存在目录时报错
- 上传路径包含 `..` 时报错
- 删除技能后树刷新正常

前端测试:

- 技能页只显示上传和删除入口
- 点击目录会展开
- 点击文件会请求内容并显示预览
- 上传目录会发送 multipart 请求
- 删除顶级技能会触发确认与删除请求
- 图标替换后页面仍能正常渲染

## 11. 风险

- `webkitdirectory` 主要由 Chromium 系浏览器支持, 但作为内部后台可接受
- 树组件当前基于 `react-arborist`, 若整行点击与展开行为不易达成, 可在保留库的前提下自定义渲染与展开状态
- 图标替换范围横跨聊天页和管理页, 需要补基础渲染测试避免遗漏
